#### 평가 기준

- 문제 점수는 길이 감소율, HB 감소율, 호환성의 평균이고, 전체 점수는 15문제의 평균이다.
  - 로컬 계산으로 88점 제출본은 88.14점이다.
  - 지정 버전 하나가 실패하면 문제 점수가 약 11.1점 깎인다.
- 실행 중 선택식은 `T/T0 + H/H0`이며 낮을수록 좋다.
  - 같은 값을 토큰 단위로 쓰면 `J = T + H/r`(`r = H0/T0`)이다.
  - 변경은 `ΔT + ΔH/r < 0`일 때 받아들인다.

#### 검증 실패 분석 요약 (다음 작업)

| 유형 | 건수 | 원인 |
|---|---|---|
| 환경에 없는 tactic | 26 | Strata 환경에는 Mathlib·Aesop이 없어 `aesop`, `tauto`, `simp_rw`가 없다. 그런데 P01 문맥의 availability 문구가 Mathlib tactic이 있다고 잘못 적혀 있다 |
| `case` 태그 위생 | 5 | P02 `induction` 태그가 `a.abs._@._hyg.0` 형태다. `induction … with \| abs` 형식은 동작한다 |
| 없는 이름 | 10+ | `List.disjoint_left` 등 Mathlib에만 있는 이름 |
| rw 패턴, `▸` | 20 | P03 목표의 `updatedStates`(def)와 lemma의 `updatedStates'`가 불일치 |
| 일반 탐색 실패 | 약 30 | grind/simp/split 실패, 남은 목표 |

하네스 쪽 원인은 다음과 같다.

1. `history`에 실패 이유가 없다. 직전 시도 하나의 오류만 전달된다.
2. `first_error`를 `find('error:')`로 찾아서 `error(lean.…):` 형식의 오류를 놓친다.
3. 오류 위치가 전체 파일 줄 번호로 나와서 모델이 자기 증명의 어느 줄인지 알 수 없다.
