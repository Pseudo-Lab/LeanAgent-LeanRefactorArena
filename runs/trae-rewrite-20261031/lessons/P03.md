# P03 InitsUpdatesComm lessons

## R1
- `exists _, rfl, ...` saves tokens vs `refine ⟨_, rfl, ..., ?_⟩` but costs ~100k HB (tries rfl/trivial on goals) -> net worse.
- Tail `nomatch InitStatesNotDefined hi k hk' ▸ UpdateStatesDefined hup k hk` beats `simpa [...] using ...` (fewer tokens, less HB).
- `grind` with closing-term args is a syntax error; grind on disjointness costs much HB.

## R2
- Dropping `have lu/li` and inlining lengths into the final `simp [List.unzip_zip, ...]` saves tokens and ~30k HB (simp_all over context is expensive).
- `$` instead of last-arg parens saves 1 token at zero HB cost.
- Adding `List.Disjoint` to simp set or switching to `exact fun k hk hk' => ...` hurts (HB up).

## R3 (profile: refine 29k, cases 15k x2, simp 45k, nomatch 27k, decl overhead ~48k)
- `cases h ▸ e` closes a `false = true` goal ~7k HB cheaper than `nomatch h ▸ e`, same tokens.
- `rw [InitStatesUpdated hi, UpdateStatesUpdated hup]` is ~20k HB cheaper than two `cases`, but +2 tokens -> net loss (break-even ~19k HB/token).
- `simp only` costs +1 token (`only` counts) for ~1k HB: never worth it here.
- Membership through `(zip ..).unzip.fst` has no cheap direct lemma; `List.of_mem_zip` doesn't apply (Missing cases).

## R4-R5 (micro)
- `delta` vs `unfold`, `apply` vs `exact`, `_` vs named `k` give ≤1k HB each; stack them only as final polish.
- Merging `apply X; exact Y` into `exact X $ Y` or `exact X (Y)` doesn't help (same or +1 token, +HB).
- Folding the disjoint tail into `simpa ... using fun ...` or `exact fun ... => nomatch` costs +2 tokens and +8-18k HB.
