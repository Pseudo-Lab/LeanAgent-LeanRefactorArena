# LeanAgent — Lean Refactor Arena

Lean Refactor Arena 대회에 참가할 **Lean 증명 리팩터링 에이전트**를 개발하는 저장소다.
문제와 원본 증명을 입력받아 리팩터링 후보를 생성하고, 검증 피드백을 바탕으로 개선을 반복하며,
최종 후보를 선택해 제출하는 전체 흐름을 개발한다.

에이전트는 원래 명제를 유지하면서 증명 토큰 길이와 Lean heartbeat를 줄이는 것을 목표로 한다.
평가 하네스는 이 과정에서 각 후보의 정확성과 개선 정도를 확인하는 구성요소다.

## 개발 범위

| 영역 | 역할 |
| --- | --- |
| 문제·실행 환경 | 문제, 원본 증명, 주변 문맥을 준비하고 Lean 버전과 의존성을 관리한다. |
| 에이전트·리팩터링 전략 | 모델 API와 도구를 연결하고, 증명 구조와 전략을 탐색해 후보를 생성한다. |
| 반복 실행 제어 | 검증 결과를 다음 시도에 전달하고, 오류 수정·재시도·예산·종료 조건을 관리한다. |
| 평가·후보 선택 | 중간 후보를 검증·측정하고 기록하며, 최종 재검증을 거쳐 후보를 선택한다. |
| 실험 분석·제출 | 전략별 결과를 비교하고, 선택된 코드를 대회 제출 형식에 맞게 정리한다. |

위 표는 프로젝트 전체의 개발 범위이며, 모든 영역이 구현 완료된 상태를 뜻하지 않는다.

## 에이전트 실행 흐름

```text
문제 입력 + Lean 환경 준비
  → 원본 증명 검증 및 기준값 측정
  → 에이전트가 리팩터링 후보 생성
  → 후보 검증 + 증명 토큰 길이·heartbeat 측정 + 결과 기록
  → 피드백을 바탕으로 오류 수정 또는 추가 개선 ↺
  → 탐색 종료 후 후보 재검증 및 최종 선택
  → 제출 산출물 생성
```

리팩터링 전략과 평가 코드는 분리한다. 전략은 후보를 생성하고 피드백을 활용하는 방법을 결정하며,
하네스는 반환된 중간 산출물을 측정·기록한 뒤 다음 시도로 넘긴다.
후보 코드, 부모 후보, 측정 결과와 선택 사유를 함께 남겨 실험을 비교하고 재현할 수 있게 한다.

## 현재 구현과 연결 지점

현재 구현된 평가 하네스는 `refactor_eval/`에 있다. 원본 측정, 중간 후보 검증,
매니페스트 기록, 최종 재평가와 후보 선택을 제공한다.

에이전트는 Python의 `propose(feedback)` 함수 또는 JSON을 주고받는 CLI adapter로 연결할 수 있다.
`run_search()`는 각 반환 후보의 평가와 기록이 끝난 뒤 다음 에이전트 호출을 수행한다.
모델 API 연동과 리팩터링 전략은 이 인터페이스에 연결해 개발하며,
대회 실행에 필요한 예산 관리와 제출 흐름도 함께 통합할 대상이다.

현재 선택 기준은 로컬 실험용 점수다. 대회 공식 평가 및 제출 결과와는 구분한다.

- [평가 흐름 HTML 개요](docs/evaluation-overview.html): 중간 측정과 최종 선택 시나리오를 정리한 문서.
- [평가 검증 기록](docs/validation.md): 실제 실행 결과와 확인한 범위.
- [에이전트용 평가 skill](skills/lean-refactor-evaluation/SKILL.md): CLI로 후보를 측정·기록할 때 따르는 절차.

평가 코드의 테스트는 저장소 루트에서 실행한다.

```sh
python3 -m unittest discover -s tests -v
```

실제 Lean 환경을 사용하는 통합 테스트와 예제 실행은 [평가 하네스 사용법](docs/evaluation.md)을 참고한다.
