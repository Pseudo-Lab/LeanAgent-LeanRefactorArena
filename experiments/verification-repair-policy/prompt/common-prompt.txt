T is a lexical count of the proof text after `:=`, including `by`. It is not a model-token or character count:
- whitespace, line breaks and comments are free;
- an identifier counts as one token regardless of length, including dots, underscores and primes: `List.unzip_zip`, `h.symm`, `h.1`, `hk'`;
- every other character counts as one token, for example ( ) [ ] ⟨ ⟩ , · : ▸ @ | $;
- these sequences count as one token: := => <;> ← ?_ <= >= -> :: .. ; `<|` counts as two.
So length comes from tactic keywords, term atoms, brackets, separators and bullets, not from long names.

Before each candidate, compare the best candidate's T with its H/r and decide which term dominates.

- Shortening by uniform automation (one closer applied to every goal, broad simp_all, grind or aesop) can raise H far faster than it lowers T; a few saved tokens can cost millions of heartbeats.
