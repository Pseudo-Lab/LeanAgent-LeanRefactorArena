## 재사용할 접근

1. **P07 — 탐색 전에 정규화.** 필요한 simp를 먼저 한 번 수행하고 Aesop의 반복 simp를 끈다. 값 역전은 inl/inr 모양에만 적용한다. 95-token 증명이87.6M HB였던 반면,103-token 변형은약10.99M으로 줄었다. 이후 LC를 직접 분해하고 canonical-form을 destruct로 바꾼101-token 후보가 세 요구 핀에서 각각3회 확인됐다.
2. **P10 — 타입으로 증거를 역추론.** 최소 집합을 반복 서술하는 대신 `d_fw ∈ (_ : Set ℕ)`에서 원래 집합/함수를 복원한다. 단사함수 대신 유한 덮개의 카드 상계도 비교한다. metavariable은 필요한 증거를 포함한 하나의 exact 표현 안에서 해결하도록 구성한다. Fin.castSucc 변경은 동치 타입이어도 강제 변환 추론이 실패할 수 있었다.
3. **P11 — 긴 중간 등식 제거.** 목표에 직접 단계별 simp를 적용하고 fiber 차이식을 필요한 덧셈식으로 바로 표현한다. 별도 진단에서는 fiber 증거가 ring보다 비쌌다. AC 정규화를 너무 일찍 적용하면 eval_C_mul 패턴을 깨뜨리므로 단계 순서가 중요하다.
4. **P05 — 계산식 대신 미분한 법칙을 증거로 사용.** 가우스 법칙에 공간 미분을 적용한 등식을 먼저 얻고 최종 식에 연결한다. 긴 calc 중간 목표를 줄였고, 마지막 field_simp/ring을 곱셈 정규화로 바꾸어 HB도 더 줄었다. change의 일부 타입을 기존 목표에서 추론하게 하는 추가 축약이 통과했다.
5. **P06 — 결합 구조와 전개 범위.** 리스트 중간 삽입 증거를 오른쪽 결합으로 맞추는 접근을 실험 중이다. rw가 정의상 같은 리스트 표현을 찾지 못하는 실패와 빈 리스트 정규화가 별도로 관찰됐다. 그 후 선형성 문맥 처리를 제한한452-token 후보, 균일한 외부 곱 인자를 존재 증거로 추론한394-token 후보가 모두 기존450-token 제출 후보보다 점수상 개선됐다. 394-token 후보의3회 checkpoint도 통과했다.

## 재현성과 자원

- 3개 에이전트가 병렬 연구한다. Lean은 공유 슬롯을 사용하며4GiB 작업은 두 슬롯을 모두 점유한다. P07의3GiB 작업이 굶지 않도록 별도 우선 실행 창을 준다.
- 1.5/3GiB에서 원본부터 발생한 memory_exception은 수학적 실패로 분류하지 않는다. 실패 실행을 보존하고4GiB 독점 실행에서 원본/seed3회를 다시 확인했다.
- 소스·도구 코드·환경 해시, plain 컴파일, target 공리 검사, nonce별 동기 HB 측정이 각 실행 폴더에 남는다. 진단용 계측은 후보 선택/점수에서 제외한다.
- P10의4.28 캐시8010개를 복원했고134개 프로젝트 의존성을 공유 슬롯에서 빌드 중이다. 로컬 ArkLib의46개 소스/manifest는 지정 공개 커밋 아카이브와 일치했다. P10의4.28 타깃은 공백 한 개 차이가 있어 별도 adapter가 실제 원문을 보존한다.

아직94점 달성은 확인하지 않았다. 전체 호환성 확인과 최종 포트폴리오 집계는 진행 중이며, 커밋과 공식 제출은 하지 않았다.
