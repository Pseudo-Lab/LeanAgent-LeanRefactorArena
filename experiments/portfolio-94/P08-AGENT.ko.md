# P08 후속 연구: 검색 비용과 증명 비용 분리

2026-10-28 연구 준비 기록. 새 실행에서 원본과 seed 재확인을 완료했고 구조 후보를 탐색 중이다. 공식 제출과 커밋은 하지 않는다.

## 기준 및 검증 구조

대회 첫 기준인 Lean 4.33.0-rc2에서 원본과 과거 185-token 최선 후보를 각각 새로 3회 측정한다. 다른 세 지정 버전은 호환성 검증으로 분리한다. `p08_agent_adapter.py`는 실제 CSLib 전체 소스를 사용하며 pinned source archive와 빌드 입력 source hash를 대조한다. 기존 빌드 receipt에 olean 출력 해시가 없으므로 현재 olean들을 새 run fingerprint에 고정하고, 평가 전후 불변성을 확인한다. 과거 receipt가 원래부터 출력 해시를 보장했다고 주장하지 않는다.

`search_agents3.py`의 공유 실행 lease, Lean 3GiB 제한, Check 컴파일·독립 공리 수집·fresh nonce 동기 측정을 그대로 사용한다. 보관 후보는 `insights-20261024-round6/validated/P08.lean`에서 가져왔다. 새 소유 경로는 `candidates/p08_agent`와 `runs/portfolio-94/p08-agent3-433`이다.

## 실험할 구조

1. I/K/S irreducibility 역전 후 종료 처리를 한곳으로 모은 `solve_by_elim` 및 Aesop 후보. 기존 proof는 대칭 case를 이미 함께 작성하지만 마지막 생성자 조합이 여전히 반복된다.
2. 역전 규칙과 관계 생성자만 등록한 짧은 Aesop 후보. 성공만으로 채택하지 않으며 HB 비용과 길이를 함께 비교한다.
3. 귀납 대상을 reduction 증명에서 SKI 식으로 변경. indexed induction이 만드는 equality transport의 커널 비용이 줄어드는지 측정한다.

## 사전 확인한 제약

- 이 관계는 disjoint redex를 동시에 줄인다. 전체 complete development를 고정 witness로 정하고 모든 중간 결과가 한 단계로 거기에 도달한다고 가정할 수 없다. 예를 들어 `I (I b)`에서 완전 축약 `b`까지는 일반적으로 한 단계가 아니다.
- 과거 `show_term` 전체 물질화는 약 3,285 tokens / 1,586,731 raw HB로 회귀했다. `Eq.ndrec`와 `HEq` 동기를 무작정 지우는 변형도 실패했다. 같은 실패를 반복하기보다 귀납 구조나 제한된 끝단만 바꾼다.
- P08은 원본 HB가 P07보다 훨씬 작다. 과거 4.30 수치를 기준으로 토큰 하나의 가치는 약 3,386 raw HB였으므로, 30-token 압축을 위해 100만 HB를 더 쓰는 후보는 손해다. 새 4.33 원본 비율을 최종 판단에 사용한다.


## 초기 측정 및 실패 진단

4.33 원본은 407 tokens / 1,381,847 raw HB, seed는 185 / 383,447이며 각각 3회 중앙값이다. 정확한 로그는 새 run의 `state.json`과 `evaluations`에 있다.

첫 네 구조 후보는 컴파일 실패했다. 공통 Aesop와 전체 역전 Aesop는 `Join`을 전개하지 않은 상태에서 탐색이 진행되지 않았다. 공통 `solve_by_elim`은 첫 `exact ⟨_, refl _, by ...⟩` 안에서 일어난 elaboration 오류가 다음 대안으로 되돌아가는 것을 방해했다. 수정안은 `refine`과 별도 tactic 실패를 이용해 되돌아가도록 한다. 식 귀납 후보는 귀납 가설이 case 인자에 추가되므로 기존 위치 기반 이름이 틀렸다. 입력 증거를 목표 타입으로 추론하는 수정안을 준비했다.

이 외에도 ① 기존 공유 case를 유지한 직접 재귀, ② S만 수동으로 두고 I/K 종료만 공통화, ③ `par.par`의 두 귀납 가설을 필요한 증거로 먼저 적용한 뒤 공통 Aesop에 전달하는 후보를 준비했다. 파일 작성은 실행 성공을 뜻하지 않으며 실제 평가 여부는 state의 attempts로 판단한다.

P07에서 유효했던 공통 자동화 압축이 P08에는 그대로 이전되지 않았다. 기준 HB가 작고, existential witness를 골라 두 관계를 동시에 만족시켜야 하므로 탐색의 되돌아가기 비용이 크다. `solve_by_elim`의 여러 목표를 다루는 `*` 변형도 현재 기본 깊이에서 실패했으며 실패를 보존했다. 깊이 확대 후보는 작성했지만 수동 구조 우선 요청에 따라 후순위로 두었다.

현재 남은 가중치 실험 이후에는 I/K/S 대칭 목표의 방향을 먼저 통일하고 pair를 직접 만드는 수동 증명과, I 가정 직접 cases를 우선한다. 가중치 후보의 Check 통과는 HB 측정 완료나 최종 채택을 의미하지 않는다.


## P08 보류 시점

평가 25회 중 12회 통과(원본/seed 포함), 최선은 기존185 /383,447로 유지했다. 가중치 조정은96 /7,147,999와172 /5,706,816으로 여전히 회귀했다. I 보조 정리 대신 가정을 직접 cases한 후보는183 /392,316으로2토큰 절약보다HB 증가8,869가 커서 소폭 회귀했다. 대칭 목표 방향을 바꾸는188/186 후보는 컴파일 실패했다.

상위 에이전트의 요청에 따라 P06 bilinear-map 구조로 전환했다. `use_discharge_IK.lean` 및 `use_discharge_all.lean`은 `use _`의 assumption discharger로 witness를 확정한 뒤 I/K/S 실제 축약만 직접 제공하는 추가 아이디어이며 미실행이다. 새 자동화 확대보다 이러한 직접 결합 압축을 후속 우선순위로 남긴다. seed는 이미 새433환경에서3회 확인했으므로 개선 없는 후보를 추가 인증하지 않았다.
