P01 OpenAI API 비교: type-hard-route, pattern

2026-11-01 · 박채원 · PR #36(type-hard-route), PR #38(pattern) 조건을 주원님 실행기로 돌린 결과

비교한 조건

다섯 조건 모두 주원님 v4의 공통 지시를 그대로 쓰고, 문제별로 덧붙이는 힌트만 다름.

  • v4: P01–P05마다 작성한 문제별 힌트.
  • common: 문제별 힌트 없음. 공통 지시만 쓰는 기준선.
  • type-hard: 원본 증명을 블록 종류(case 분기, calc 계산, have 중간 명제)로 나눠 가장 큰 종류를 고르고, 그 종류의 전략 문장 하나를 자동으로 붙임.
  • type-hard-route: type-hard에 두 가지를 더함. ① 원본에서 보이는 신호로 시도할 증명 경로 2–3개와 "연속 3번 개선이 없으면 다음 경로로" 전환 규칙. P01에는 fun_induction substOld가 첫 경로로 붙음. ② 가장 짧은 증명이 최선은 아니라는 평가값 기준 문장.
  • pattern: 블록 종류 대신, 웜업 원본과 88점 제출본을 비교해 뽑은 공통 단축 패턴(기존 정리로 대체, have 연쇄 제거, 넓은 자동화 축소 등) 중 원본에 신호가 보이는 것만 붙임.
요약
  • type-hard-route는 평가값 0.464로 common(0.520)과 기존 type-hard(0.520)보다 좋아졌고, 36토큰으로 v4(35토큰)와 거의 같은 길이까지 감.
  • pattern은 0.546으로 common보다 성능이 좋지 않았음. 증명 모양이 기존 type-hard의 보조 정리 증명과 거의 같음.
  • Claude 근사 실험과 같은 순서(type-hard-route < pattern)가 GPT에서도 나옴. 조건마다 한 번씩 돌린 결과임.

해석

  • type-hard-route: 기존 type-hard에 경로 메뉴(fun_induction substOld를 첫 경로로)와 평가값 기준 문장을 더한 조건. 기존 type-hard는 보조 정리로 HB만 낮추고 101토큰에 머물렀는데, 이번엔 36토큰까지 줄어 경로를 바꾼 것으로 보임. v4와의 차이 0.033은 HB(1,807k 대 1,653k)에서 남.
  • pattern: 유형 대신 웜업에서 뽑은 공통 패턴 문장을 붙인 조건. GPT는 109토큰, 1,022k로 기존 type-hard의 combine 보조 정리 증명과 거의 같은 결과를 냄. Claude 실험에서는 fun_induction을 찾았지만 GPT는 찾지 못함. P01에는 정의를 따라 나누기가 첫 패턴으로 붙지만, 패턴이 4개라 경로 지시가 상대적으로 약했을 수 있음.

한계

  • 조건마다 한 번씩이고, 주원님 실행과 날짜가 다름.
  • P01의 경로 단서는 v4 결과를 보고 만든 것이라 P01은 유리한 문제임. 효과는 본 대회 문제에서 확인해야 함.
  • golf는 v4와 type-hard-route에서만 줄었고, pattern에는 돌리지 않음.

다음

  • v4처럼 직접 작성한 힌트가 P01에서 가장 좋았지만, 본 대회 새 문제 45개 안팎에 마감(11월 4일 21시)까지 문제별 힌트를 직접 쓰기는 어려움. 그래서 자동으로 붙는 type-hard-route를 기본 조건으로 두고 common과 함께 돌린 뒤 문제마다 최고점을 고름.
  • 원본이 길거나 점수 여지가 큰 몇 문제는 직접 작성한 힌트를 더해 보는 방식으로 v4의 장점을 살림.
  • golf 결과가 나오면 이 표에 추가.
