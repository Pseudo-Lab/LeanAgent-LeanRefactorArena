# P01·P13 독립 서브에이전트 반복

사용자 요청: P01과 P13을 각각 두 번, 독립 에이전트로 실행하고 기록을 분리한다.

## 조건

- 실행 ID: `P01-r1`, `P01-r2`, `P13-r1`, `P13-r2`.
- 각 실행은 새로운 `fork_turns=none` 서브에이전트가 담당한다.
- 메인 채팅을 포함한 동시 슬롯은 4개다. 따라서 독립 서브에이전트 3개를 시작하고,
  자리가 나는 즉시 네 번째를 시작한다. **풀이 에이전트 4개가 동시에 실행됐다고 기록하지 않는다.**
- 공통 Lean 버전은 v4.26.0이다. P01은 Strata `451e5f047bafa010d178856db76c00029bfa4d7f`,
  P13은 Mathlib `2df2f0150c275ad53cb3c90f7c98ec15a56a1a67`을 사용한다.
- 같은 문제의 두 반복에 원본·소스·프롬프트·컴파일 문맥·하네스 코드를 동일하게 제공한다.
  P01 원본은 수집 메타데이터와 고정 소스 파일 SHA256을 대조한다.
  P13 원본은 기존 benchmark 원본 메타데이터를 사용한다.
- 이전 개선 풀이·다른 실행의 후보·기록은 에이전트 입력에서 제외한다.
- 실행마다 후보 제안은 3번이다. 실패한 후보도 1번으로 센다. 별도 비공개 후보 테스트를 금지한다.
- 각 후보는 일반 컴파일 1회, 계측 컴파일 3회를 수행하고 raw heartbeat 중앙값으로 비교한다.
- 원본을 fallback으로 유지하고 최선 후보를 별도 재검증한다.

## 최소 하네스와 연결 방식

`subagent_trials.py`는 이미 준비된 로컬 라이브러리와 Codex 서브에이전트를 연결하는 실험용 어댑터다.
기존 `harness.py`의 명제 고정·응답 파싱·측정·후보 순위·피드백·해시 기록 함수를 재사용한다.
외부 의존성을 지원하지 않는 기본 `load_config`를 우회해 준비된 환경을 명시적으로 연결하므로,
기본 `smoke.json`으로 실제 대회 문제를 실행한 결과와 혼동하지 않는다.

코디네이터가 원본 검증과 최초 요청을 준비한다. 에이전트는 자신의 `requests/NNN.json`을 읽고
`responses/NNN.json`에 증명 본문을 저장한 뒤 고정된 worker의 `submit`을 호출한다.
worker만 검증 결과·상태·최종 선택 기록을 작성한다. 세 번 제출 후 `finish`, `replay`를 실행한다.

각 실행의 입력·응답·후보·컴파일 소스·로그·상태·최종 증명·요약은 서로 다른 디렉터리에 둔다.
컴파일러와 사전 빌드된 라이브러리만 읽기 전용 사용 정책으로 공유한다.
별도 HOME·임시 디렉터리·컴파일 작업 디렉터리를 사용하며 Lean에 개인 인증 환경을 전달하지 않는다.
이것은 OS 수준 파일·네트워크 격리가 아니다. 접근 범위 제한은 서브에이전트 지침이기도 하다.

## 해석 범위

- Codex 서브에이전트의 정확한 모델 backend ID·내부 시스템 문맥·사용량·비용은 이 어댑터로 관측하지 못한다.
- 제안 3번이 내부 모델 호출 3번이라는 뜻은 아니다. 사용량·비용은 `null`로 기록하며 0으로 꾸미지 않는다.
- 각 실행 안에서 서브에이전트 대화가 유지된다. 매 단계 새 API 호출에 완전히 통제된 문맥만 제공하는
  기본 하네스와 같은 조건이라고 주장하지 않는다.
- OpenRouter를 호출하지 않는다. 이 실행으로 대회 제출용 API 비용 준수나 공식 성능을 입증하지 않는다.
- 같은 호스트의 병렬 프로세스는 자원을 공유한다. 벽시계 시간과 자원 경합의 영향을 고려한다.
- 문제당 두 반복은 동작·변동 관측용이다. 일반적인 성능 안정성의 통계적 입증으로 해석하지 않는다.

전체 로컬 기록은 `runs/first-harness-jwkweon/p01-p13-subagents-20261024/`에 보존한다.
`cohort.json`은 고정 조건, 완료 후 `cohort-summary.json`은 네 실행의 상태·지표·재생·무결성 검사 결과를 담는다.

## 이번 실행 결과

네 실행 모두 후보 제안 3회, 최종 Lean 검증, 기록 재생, 고정 입력 무결성 및 요청·상태 귀속 검사를 통과했다.
요약은 [subagent-results.json](subagent-results.json)에 보존한다.

| 실행 | 원본 → 최종 선택 토큰 | 선택 시점 raw heartbeat 중앙값 | 로컬 점수 |
| --- | --- | --- | --- |
| P01-r1 | 313 → 313 | 5,173,306 | 1.0000 |
| P01-r2 | 313 → 313 | 5,173,304 | 1.0000 |
| P13-r1 | 1,769 → 415 | 3,335,984 | 0.1317 |
| P13-r2 | 1,769 → 618 | 5,555,026 | 0.1987 |

점수는 원본이 1이며 낮을수록 좋다. 공식 대회 점수가 아니다.
P01의 검증된 짧은 후보들은 heartbeat 증가로 원본보다 나쁜 점수를 받았다.
따라서 두 실행의 최종 선택이 같다는 사실은 개선 성공이나 동일 탐색 경로를 뜻하지 않는다.
P13은 두 실행 모두 개선했지만 선택된 코드와 성능은 달랐다.

고정된 문제·소스·프롬프트·컴파일 문맥·실행 코드의 해시는 문제별 두 반복에서 모두 같았다.
다만 P01 원본 측정은 5,173,306과 5,173,304, P13은 115,674,914와 115,674,916이었다.
그 숫자를 모델 입력에 포함했으므로 **첫 요청 전체의 바이트는 문제별 두 반복에서 달랐다.**
독립적인 전체 파이프라인 반복의 관측 결과로 보존하며, 같은 모델 입력에서 생긴 차이로 해석하지 않는다.
모델 변동만 분리하려는 다음 실험에서는 기준값을 미리 고정하고 실행별 재측정은 별도 관측값으로 저장한다.
