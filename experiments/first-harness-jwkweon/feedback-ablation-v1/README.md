# 오류 피드백 구조화 실험

P01·P13에서 naive A 프롬프트를 고정하고, 실패한 Lean 컴파일의 오류 피드백 정책만 L(기존)과 S(구조화)로 비교합니다. 두 조건 모두 `details` 상한은 1,600자입니다. S는 같은 검증에서 이미 저장한 원문 로그의 첫 오류·목표·주변 가정을 선택해 완전한 JSON 문자열로 전달합니다. JSON 표기만의 효과를 분리하는 실험은 아닙니다.

기존 `harness.py`, 평가기와 `subagent_trials.py`는 변경하지 않습니다. 실험 전용 worker 복사본에서 제출·replay의 피드백 호출만 분기하며, 성공·응답 형식 거절·컴파일 오류 이외의 피드백은 기존과 같습니다. 추가 검증, 라이브러리 열람, 전략 지침, 후보 예산은 추가하지 않습니다.

문제별·조건별 새 solver 두 개, 실행당 10개 후보, 최대 두 solver 동시 실행으로 총 8개 실행·80개 후보를 평가합니다. 모든 실행은 처음부터 10회 예산을 알고 있으며 3·6회는 그 과정의 중간 관측입니다. 같은 문제의 네 실행에서 첫 요청 JSON은 바이트 단위로 동일합니다.

주 관측값은 3회차에 원본보다 낮은 비용을 찾은 실행 수입니다. 초기 유효 후보 수, 최초 유효·개선 회차, 3/6/10회 비용과 실제 오류 피드백 노출도 함께 기록합니다. 조건당 두 번이므로 통계적 우위나 일반화를 입증하는 실험은 아닙니다.

[사전 설계](design.json), [변경 코드](worker.py), [구조화 추출기](error_feedback.py), [검증 기록](implementation-notes.json)을 보존합니다. 원문 실행은 `runs/first-harness-jwkweon/feedback-ablation-20261025/`에서 관리합니다.

2026-10-25 총 8개 실행·80개 후보를 완료했습니다. 63개 후보가 통과했고 17개는 일반 컴파일 오류로 거절됐습니다. 선택본 8개 모두 최종 검증·기록 replay를 통과했습니다. 3/6/10회 관측 24건과 전체 로그 감사를 완료했고, P01 런타임 11,532개·P13 런타임 95,212개 파일의 전후 해시가 일치했습니다.

[결과·반복별 수치·그래프](results/README.md)에서 확인할 수 있습니다. P01의 3회차 개선 실행 수는 L 0/2, S 1/2였고 초반 유효 후보 수는 두 조건 모두 평균 1.5/3이었습니다. 10회차 평균 비용은 L 0.418380, S 0.358837입니다. P13의 3회차 개선은 두 조건 모두 2/2였고, 10회차 평균 비용은 L 0.119328, S 0.140107입니다. 구조화 조건의 10회차 평균 비용이 P01에서는 14.23% 낮고 P13에서는 17.41% 높아, 일관된 성능 향상은 확인하지 못했습니다.

P01-L-r1·P13-S-r1은 계정 사용량 제한 후 사용자의 재개 지시에 따라 같은 solver 문맥에서 이어갔습니다. 완료 후보 재시도나 예산 추가는 없었으며 중단 사실을 결과에 기록했습니다. 조건당 두 번의 탐색이며, 오류 정보 선택과 구조화가 함께 바뀌므로 JSON 형식만의 효과를 입증하는 결과도 아닙니다.
