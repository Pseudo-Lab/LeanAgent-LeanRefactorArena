# Trae 추가 재작성: 검증 결과와 P12 재개 기록

2026-10-31~11-01에 기존 팀 제출 증명을 추가로 편집한 개발 실험이다. P01~P09는 아래 대표 버전에서 추가 편집본의 최종 검증을 통과했고, 로컬 제출 파일에도 같은 증명이 들어 있다. P13·P15에도 최종 검증 기록이 있다. P14는 screening 이후 최종 검증 요약이 없다. P12는 디스크 부족으로 중단된 Round 2 체크포인트에서 재개했다가 추가 측정을 중단했다. 최종 검증과 기존 제출본 비교는 완료하지 않았다.

이 PR은 증명 후보와 측정 근거를 공유한다. 공용 `submissions/warmup/best`, manifest, 대시보드와 공식 제출은 변경하지 않는다. 기존 팀 증명을 출발점으로 썼으며 전체 증명의 신규 저작이나 독립적인 모델 성능으로 주장하지 않는다. 이번 PR은 확보한 후보와 기록을 공유하는 단계로 마무리하며 draft를 유지한다. 다른 문제의 미확인 지정 버전과 P14 최종 검증은 별도 후속 과제이며, 확인 전에는 공용 제출 후보로 채택하지 않는다.

## 어떤 변경이 효과가 있었나

- **P01: 단순 귀납 분기를 직접 닫기.** `simp`·`grind`가 처리하던 단순한 경우에 `exact .inl`, `exact .inr`, `assumption`을 사용했다. 이후 분기 순서와 `rotate_left`를 조정했다. 토큰 하나 감소보다 HB 감소가 큰 사례다.
- **P02: 구조 분해와 말단 목표 처리를 분리하기.** `Sublist.append`로 먼저 나눈 다음 `assumption`, `List.nil_sublist`, `List.Sublist.refl` 순서의 작은 전술 묶음으로 닫았다. 자동 탐색의 실패 비용을 줄여 토큰이 하나 늘어도 목적값이 좋아졌다.
- **P03·P04: 작은 변경을 합산하기.** 불필요한 길이 관련 `have`를 제거하고, 모순 목표의 `cases`, 등식 치환 `▸`, 마지막 인자의 `$`, `refine`→`apply` 등을 비교했다. 이름 접두어를 줄이는 것만으로 토큰이 줄어든다고 가정하지 않았다.
- **P05: 미분 증명 묶기.** 반복된 미분 가능성 선언을 `HasFDerivAt`으로 묶고, `Space.div`를 펼치는 위치와 중간 선언을 정리했다. `by decide` 일부를 직접 근거로 바꿨다.
- **P06: 중간 가설 대신 직접 재작성하기.** `f`의 결과를 두 번 별도 가설로 저장하고 정리하던 부분을 `rw [f _ ?_, f _ ?_]`와 후속 목표 처리로 바꿨다. 앞쪽 단순화와 경우 분해도 조정했다.
- **P07: 길이와 HB의 절충.** Aesop 규칙의 위치·표기와 후속 `simp_all`을 조정했다. 최종 HB는 출발점보다 늘었으므로 HB 단독 개선으로 소개하지 않는다.
- **P08: 증명항 구성 방식 바꾸기.** 중첩 `.elim`·람다와 긴 생성자 적용을 `obtain`, `constructor`, `apply` 구조로 바꿨다. 줄 수 대신 실제 토큰과 HB를 비교했다.
- **P09: 실패하는 탐색 대안 줄이기.** `repeat' first`의 반복 탐색을 명시적인 두 번의 경우 처리와 남은 목표 처리로 바꿨다. 토큰 하나 증가를 HB 감소가 상쇄했다.

이는 이 후보들에서 관찰한 결과다. 각 변경의 독립 효과를 모두 분리한 통제 실험이나 새로운 알고리즘의 우선권 주장은 아니다. P01~P09의 세부 성공·실패 경로는 보존된 `lessons/`와 후보 소스에서 확인한다.

## P10~P12: 다른 출발점의 자동 루프

9개 정규식 규칙을 적용하는 `auto_rewrite.py`는 P10~P12에서 기존의 짧은 제출본 대신 긴 공식 원본으로 시작했다. 이 결과를 기존 제출보다 개선됐다고 취급하지 않는다.

| 문제 | 기존 제출 토큰 | 원본 토큰 | 자동 루프의 후보 토큰 | 상태 |
|---|---:|---:|---:|---|
| P10 | 257 | 1463 | 1457 | v4.31.0 최종 검증, 역사적 점수 33.48. 기존 제출과의 새 동일 환경 비교 전 |
| P11 | 248 | 1906 | 1905 | v4.31.0 최종 검증, 역사적 점수 33.35. 기존 제출과의 새 동일 환경 비교 전 |
| P12 | 156 | 1353 | 1336 | Round 2 screening J=2690.97, 최종 검증 전. workers 1 재개 측정 중단 |

P10은 `simp only [ne_eq, d_H]`→`simp`, P11은 두 `· omega` 줄→`all_goals · omega`를 채택했다. P10 첫 `apply`→`exact` 채택 당시 기준 측정은 timeout이었으므로 그 변경만의 원본 대비 개선을 입증하지 못했다. P12는 `simp only` 축소 뒤 지역 보조정리의 `r_init` 타입 표기를 제거했다. 중단 원인은 디스크 부족이며, 재개 첫 기준 측정에서도 timeout이 발생했다. 이후 통과한 후보가 있지만 새 라운드 전체와 최종 검증은 아직 끝나지 않았다.

시간 초과·메모리·저장 공간 오류를 증명 오류나 개선 없음으로 세지 않아야 한다. 기존 스크립트는 하위 측정 실패 후 빈 결과를 개선 없음으로 세는 한계가 있다. 이번 기록은 이를 성능 결론에 사용하지 않는다. 기존 제출을 교체하려면 현재 제출과 후보를 같은 환경에서 검증하고 더 좋은 쪽을 선택해야 한다.

## 근거와 확인 방법

`summary.json`은 후보 해시, 비교 출발점, 역사적 최종 검증, 지정 버전 대비 확인 범위와 증거 파일 목록을 담는다. `candidates/`는 이 기록의 후보이며 공용 제출 후보를 대체하지 않는다. P13은 259→244토큰/HB2850k, P15는 281→122토큰/HB1082k의 역사적 최종 검증을 보존한다. P14의 55→54토큰 후보는 최종 검증 전으로 표시한다.

원시 로그·전체 검사 소스·출발 증명·환경 fingerprint·당시 자동 루프·로컬 하네스 차이는 작업 브랜치의 증거 보존 커밋에 담고 최종 트리에서는 제거한다. 보존 커밋은 `summary.json`의 `evidence_archive_commit`으로 찾는다. 다음 명령은 Git 이력에서 해당 증거를 읽어 파일 해시, 후보 토큰, 실제 Lean 로그의 대상 정리·허용 공리·3회 HB 중앙값을 대조한다. Lean이나 모델을 새로 실행하지 않는다.

```bash
python3 experiments/trae-rewrite/check.py
```

얕은 clone에 증거 커밋이 없다면 `git fetch origin 50a01f060e446cf66c521513a806ac25b21cdda2`로 먼저 가져온다.

새 Lean 실행은 저장소의 `skills/lean-proof-shortening/SKILL.md` 절차로 해당 문제의 고정 입력·환경을 준비한 다음 `experiments/proof-golf/verify.py`에 `candidates/PXX.lean`을 전달한다. 이전 로컬 환경의 경로·timeout·메모리·소스 revision은 보존 증거에서 확인한다. 후보를 바꿨다면 지정 버전 모두를 새로 검증한다.

역사적 H0와 공식 기준 H0가 다른 경우 원래 점수를 유지하면서 공식 분모로 다시 계산한 값도 `summary.json`에 따로 저장한다. 이 값 역시 당시 설정 버전만의 로컬 값이다. 기존 #17의 두 지표 평균과 이 세 지표 평균을 직접 비교하지 않는다.

이번 수집·결정적 재작성 단계에는 유료 API 호출이 없다. 앞선 대화형 후보 생성의 모델 비용 장부는 확보되지 않았으므로 전체 실행의 비용 0이나 대회 API·예산 조건 충족을 주장하지 않는다.
