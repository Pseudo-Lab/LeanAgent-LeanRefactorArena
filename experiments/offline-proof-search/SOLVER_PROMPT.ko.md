# 로컬 증명 최적화 solver 지침

입력은 실행 디렉터리와 원본 선언이다. 목표는 고정 statement와 사용 가능한 원문 문맥을 유지하며, 최종 검증된 `L/L₀ + H/H₀`를 최소화하는 것이다. 로컬 탐색 시간이나 실패 후보 수는 점수 벌점이 아니다. 별도 유료 서비스 호출은 이 지침이 허가하지 않는다.

## 관찰하고 선택하기

1. `config.json`, `environment.json`, `original.lean`, `seed.lean`, `state.json`을 읽는다. 원본·시작 후보·잠정 best·확인된 후보를 구분한다. 과거 결과나 모형 수치를 새 환경의 성능으로 대신하지 않는다.
2. `lookup.py`로 원래 prefix와 import 관계에서 목표의 타입, 가정의 표현, 사용할 수 있는 정의·정리를 찾는다. 검색 hit는 타입/가시성/호환 검증 전의 단서다. target 자체와 suffix, target에 의존하는 결과는 재사용하지 않는다.
3. 전체 구조 대체, 기존 witness/instance의 직접 전달, 표현 변환 제거, 중간 명제 압축 중 현재 후보에 근거가 있는 경로를 선택한다. 단계 순서를 고정하지 않는다. 새로운 정의·helper를 제출 범위 밖으로 옮기지 않는다.
4. 후보는 원본 statement를 바이트 단위로 보존한 완전한 선언 파일로 저장하고 `submit`으로 검증한다. 편집 의도와 근거 위치를 짧게 기록한다. 상세한 사고 과정이나 긴 가설 카드는 필요하지 않다.
5. 실패하면 첫 실제 오류를 읽는다. 인자·정의의 표현 차이인지, 필요한 명제가 사라졌는지 구분한다. 수리 후보는 별도로 저장하고 다시 검증한다. 실패·timeout의 부분 HB를 점수로 사용하지 않는다.

## 깊게 탐색하기

- 충분히 넓게 찾은 뒤, 최종 코드에서는 선택된 정리·규칙·증거만 전달한다. 탐색을 매번 재수행하는 짧은 tactic이 항상 좋은 최종 코드인 것은 아니다.
- 반대로 모든 인자를 명시하거나 큰 proof term을 덤프하는 것도 목표가 아니다. 과한 표기를 줄여보고 컴파일·Length·HB를 함께 확인한다.
- 구조 후보를 얻으면 `search`와 `polish`로 반복 가능한 편집을 시험한다. 이 도구의 현재 편집 종류가 소진돼도 전체 증명 탐색이 끝난 것은 아니다. 새 구조를 추가해 재개할 수 있다.
- 구간 진단은 별도 출력 경로에서 수행하고 계측 부담을 확인한다. 진단용 tactic이나 계측 밖 helper를 제출 후보에 넣지 않는다.
- 현재 best만 고집하지 않는다. 길이/HB Pareto 후보와 구조가 다른 후보를 다시 살핀다. 편집을 결합할 때는 전체 선언을 재측정한다.
- 같은 proof term이라도 소스 표기가 다르면 HB가 다를 수 있다. 중복 제거는 최종 항만으로 하지 않는다.

## 2026-10-28 실험에서 추가한 탐색 관점

- 인접한 `simp_rw`를 한 번의 `simp only`로 합치는 후보를 시험한다. 반복이 필요 없는 구간에서는 `simp +singlePass only`도 별도 후보로 비교한다. RHS에 새로 생기는 redex를 다시 처리해야 한다면 실패할 수 있으므로 일괄 적용하지 않는다.
- 설정의 의미와 표기를 분리한다. 긴 `(config := { singlePass := true })`와 짧은 `+singlePass`도 서로 다른 소스로 측정한다. 설정을 끄거나 정리를 명시한다고 비용이 반드시 줄어드는 것은 아니다.
- 소스의 정리 본문에 직접 적힌 binder 외에 section에서 일반화된 explicit 인자도 확인한다. `apply lemma`를 완성된 term으로 바꿀 때는 이 인자를 누락하지 않는다. 잘못 적용한 초안의 실패를 전략의 성능 결과로 해석하지 않는다.
- 전체 best가 되지 않은 단일 변경도 결합 요소로 보존한다. 예를 들어 귀납 recursor 직접 적용은 단독으로 당시 best를 넘지 못했지만, 단순화 통합과 결합했을 때 유용했다. 결합 후보를 새로 측정하고 개별 개선량을 단순 합산하지 않는다.
- 후보 선택의 교환비는 원본 `H₀/L₀`로 계산한다. 토큰 하나를 더 쓰는 대신 그보다 많은 raw HB를 절약해야 종합점수가 좋아진다. 서로 매우 가까운 후보의 미세한 점수 순위를 큰 성과로 표현하지 않는다.
- 계측할 때 선언 시작, 본문 진입, 본문 구간, 선언 완료를 구분한다. 본문 진입 전 관측 비용을 모든 proof나 공식 worker의 엄밀한 하한으로 단정하지 않는다. 진단값은 비계측 최종 측정을 대체하지 않는다.

## 채택과 보고

잠정 개선은 한 번 측정한 값이다. `certify`로 원본·시작 후보·선택 후보를 새로 반복 측정하고, 같은 코드 SHA로 필수 pin을 확인한다. 코드·문맥·로그·nonce·공리 감사가 끝난 후보만 전 버전 성과로 보고한다. 새로운 검색 공간을 탐색하지 않은 채 전역 최적이라고 표현하지 않는다.

현재 API는 기존 P12 adapter의 실행형 prototype이다. 다른 문제에는 그 문제의 전체 원문·필수 환경·계측 adapter를 먼저 연결해야 한다. 연구의 편의상 한 번의 작업을 여러 호출로 나눌 수 있지만, 호출당 `--steps`를 전체 탐색 예산으로 해석하지 않는다. 오래 걸린 방법도 최종 증명이 좋으면 채택한다.
